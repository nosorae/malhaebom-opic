# 0037. 스크립트는 화면에 들어갈 때 만들고 실패는 분석 이유 값으로 돌려준다

- 상태: 채택
- 날짜: 2026-11-07

## 배경

코치 세션이 끝나 스크립트 단계로 가면(30분, 피드백 끝, 리허설 없이 넘김) 받아쓰기, 메모, 표현 카드, 목표 등급을 글 모델에 한 번 보내 스크립트를 만든다(F14.1). 요청은 키가 없거나, 연결이 없거나, 한도에 닿거나, 빈 칸이 온 응답으로 실패할 수 있다. 사용자는 30분을 들인 대화가 스크립트로 남기를 기다리므로, 실패해도 받아쓰기를 잃지 않고 이유를 보고 다시 시도할 수 있어야 한다.

## 후보

1. 코치 엔진(`LiveCoach`)이 세션을 끝낼 때 바로 만들고, 실패는 예외로 던진다
2. 분석 작업 표(`analysis_job`)에 스크립트 작업을 넣어 대기열이 뒤에서 만든다
3. 스크립트 화면에 들어갈 때 저장된 스크립트가 없으면 만들고, 포트는 `ScriptResult`(성공 또는 `AnalysisError` 이유)를 돌려준다

## 결정

3을 고른다.

- `ScriptWriter.write(session, question)` 과 `polish(edited, expressions, question, targetGrade)` 는 `ScriptResult<T>` 를 돌려준다. 실패 이유는 답변 분석과 같은 `AnalysisError` 를 쓴다
- 세 칸 가운데 하나라도 비었거나 JSON 을 못 읽으면 `Rejected` 다. 자동으로 다시 요청하지 않는다
- 코치 대화 화면은 세션이 끝나면 스크립트 화면으로 바뀌고, 스크립트 화면이 `coach_script` 에 없을 때만 만든다. 받아쓰기는 세션 표에 남아 다시 시도하면 같은 입력으로 다시 만든다
- 모델은 설정에서 고른 분석 모델이고, 프롬프트는 시험 팩이 채워 어댑터(`GeminiScriptWriter`)에 넘긴다

## 이유

스크립트는 녹음을 싣지 않는 글 요청 한 번이라 수 초면 끝난다. 후보 2는 앱이 뒤로 가도 이어 가는 장점이 있지만 작업 종류, 재시도 정책, 진행 알림을 하나 더 늘려야 하고, 사용자는 어차피 화면 앞에서 결과를 기다린다. 후보 1은 엔진이 글 모델까지 알게 되고, 실패를 받을 화면이 없어 사용자가 이유를 볼 수 없다.

실패 이유를 답변 분석과 같은 값으로 두면 키 오류, 연결 없음, 한도를 화면이 같은 기준으로 가른다. 자동 재요청을 하지 않는 것은 화면에 다시 시도가 있고 무료 키의 하루 한도를 아끼기 위해서다.

## 결과

만드는 중에 앱을 끄면 요청이 버려지고, 다음에 스크립트 화면(기록 탭의 스크립트 줄이나 같은 세션)을 열 때 다시 만든다. 그때까지 기록 탭에는 그 세션의 스크립트 줄이 없다. 끝난 세션의 스크립트를 만들지 못한 채 화면을 떠나면 다시 열 길이 없으므로, 이게 문제가 되면 기록 탭에 "스크립트를 만들지 못한 세션" 줄을 더하거나 후보 2로 옮긴다.
