# 0045. 오디오 끼어듦은 오디오 라이브러리가 알리고 효과음은 코드로 만든다

- 상태: 채택
- 날짜: 2026-11-20

## 배경

말하기 연습은 통화가 오거나, 다른 앱이 소리를 가져가거나, 이어폰을 빼면 일시정지하고 돌아오면 이어서 할지 묻는다(F16.14). 상태가 바뀔 때는 서로 다른 효과음 다섯을 낸다(F16.19). 설계(design.md 12.2)는 끼어듦을 Android 서비스와 iOS 앱 쪽에서 받고, 효과음은 플랫폼 쪽 소리 파일로 둔다고 적었다.

Android 의 오디오 포커스 잃음은 포커스를 요청한 그 요청 객체의 듣는 함수로만 온다. 포커스는 `libs/duplex-audio` 가 마이크를 열 때 요청한다. iOS 는 전화가 끝나면 멈춘 `AVAudioEngine` 을 다시 켜야 마이크가 다시 들어오는데, 엔진도 같은 라이브러리 안에 있다.

## 후보

1. 끼어듦을 플랫폼 앱 코드가 따로 듣는다. Android 서비스가 포커스를 한 번 더 요청하고, iOS 앱이 알림을 듣는다
2. `DuplexAudio` 가 끼어듦 시작과 끝을 흐름으로 내고, 앱 공통 `RunningPractice` 가 그것으로 일시정지와 다시 시작을 정한다
3. 효과음을 소리 파일 다섯 개로 두고 Android 리소스와 iOS 번들에 따로 넣는다
4. 효과음을 공통 코드에서 음 높이 몇 개의 짧은 소리(PCM)로 만들고 플랫폼은 틀기만 한다

## 결정

2와 4를 고른다.

- `DuplexAudio.interruptions` 는 끼어듦 시작(`Began`)과 끝(`Ended`), 이어폰 빠짐(`Unplugged`)을 낸다. Android 는 포커스 잃음(소리 줄이기 요청은 뺀다)과 이어폰 빠짐 방송, iOS 는 세션 끼어듦 알림과 이어폰 빠짐 경로 바뀜이다
- Android 는 포커스를 아주 잃은 뒤 다음 코치 소리를 낼 때 포커스를 다시 요청한다. 아주 잃으면 다시 요청하기 전에는 전화가 와도 알림이 오지 않는다
- iOS 마이크 흐름은 끼어듦이 끝나거나 엔진 설정이 바뀌어 엔진이 멈췄으면 탭부터 다시 연다. 끼어듦 동안의 설정 바뀜으로는 열지 않고, 열지 못해도 흐름을 닫지 않고 다음 알림에서 또 연다. 흐름이 닫히면 끝 효과음이 다 나갈 시간을 기다린 뒤 오디오 세션을 놓는다
- `RunningPractice` 는 끼어듦으로 멈춘 연습만 끼어듦이 끝날 때 다시 시작한다. 사용자가 멈췄거나 그 사이 명령을 넣었거나 이어폰이 빠져 멈췄으면 그대로 둔다
- 효과음은 `Chime` 다섯이고, 올라가는 음은 시작과 다시 시작, 내려가는 음은 일시정지와 끝, 높은 두 번은 표현 저장이다. 어떤 효과음을 낼지는 앞뒤 상태로 공통 코드가 고른다

## 이유

후보 1은 Android 에서 같은 앱이 포커스를 두 번 요청하게 된다. 서비스의 요청이 라이브러리의 요청을 밀어내 라이브러리 쪽이 포커스를 잃었다고 보거나, 둘이 엇갈려 끝을 놓친다. iOS 는 끼어듦을 알아도 엔진을 다시 켤 곳이 라이브러리 밖이라 앱 코드가 엔진을 알아야 한다. 후보 2는 라이브 코치도 같은 흐름을 받아 쓸 수 있고, 다시 시작 규칙(사용자가 멈춘 것은 두기)을 공통 테스트로 본다.

후보 3은 같은 소리를 두 플랫폼에 두 벌 넣고 Xcode 프로젝트의 리소스 목록을 고쳐야 한다. 소리 다섯은 음 몇 개라 코드 몇 줄로 만들고, 서로 다른 소리인지와 iOS 플레이어가 여는지를 테스트로 본다.

## 결과

- 끼어듦 처리는 실기기에서만 확인된다. 통화용 오디오(Android `VOICE_COMMUNICATION`, iOS `.voiceChat`)로 재생하는 중에 이어폰 버튼이 앱으로 오는지도 실기기 확인이 남는다. 오지 않아도 말과 알림 버튼으로 모든 조작이 된다
- 효과음은 알림 소리 용도로 틀어 이어폰이 있으면 이어폰으로 나간다. 소리가 작거나 겹치면 음 높이와 크기 값만 바꾼다
- 전화가 끝나 다시 시작하면 코치가 이어서 할지 한 번 묻는다. 묻는 글은 시험 팩의 `resumed` 알림이다
