# 0046. 연습 화면은 연습 조작 경계 하나로 지켜보고 카드 빼기는 지운 뒤 다시 써서 되돌린다

- 상태: 채택
- 날짜: 2026-11-20

## 배경
말하기 연습 화면(`ui/feature-speaking`)은 앱 층의 `RunningPractice` 가 들고 있는 세션을 지켜보기만 한다(ADR 0038). 화면 모듈은 앱 층을 의존할 수 없어서 화면이 연습 상태와 명령에 닿을 길이 필요하다. 연습 탭 맨 위 카드 둘(F16.1)은 한 문항 연습 화면 모듈(`ui/feature-practice`)에 그려야 하고, 연습 정리 화면의 밀어서 빼기는 5초 안에 되돌릴 수 있어야 한다(F17.7).

## 후보
1. 화면 모듈에 연습 조작 경계(`PracticeControl`: 상태, 목소리 크기, 시작, 명령)를 두고 `RunningPractice` 가 바로 구현한다. 연습 탭 카드는 앱 층이 연습 탭의 칸(`header`)에 넣는다. 카드 빼기는 바로 지우고 되돌리기는 같은 id 로 다시 쓴다
2. 화면이 세션 상태를 저장소(`speaking_active`)에서 읽고, 명령은 앱 층 람다로 받는다. 연습 탭 화면 모듈이 말하기 연습 화면 모듈을 의존해 카드 ViewModel 을 함께 든다. 카드 빼기는 화면에서만 숨겼다가 5초 뒤에 지운다

## 결정
1을 고른다.
- `PracticeControl` 은 `ui/feature-speaking` 에 두고 `RunningPractice` 가 구현한다. 조작 명령 `PracticeCommand` 도 `ui/feature-speaking` 에 두어 화면 버튼, 알림 버튼, 이어폰 버튼이 같은 값을 `PracticeControl.command` 로 넘긴다
- 연습 탭 화면은 `header` 칸 하나만 받고 무엇을 넣을지는 `RouteContent` 가 정한다
- 시작 시트는 열 때마다 새 키로 ViewModel 을 만들어 고른 값이 이번 연습에만 쓰이고(F16.2) 그때 이어폰 연결로 소리 환경을 고른다
- 밀어서 뺀 카드는 바로 지우고, 되돌리기는 지운 카드를 같은 id 로 다시 쓴다. 신고는 지우고 신고 수를 올리며 되돌리지 않는다
- 말로 복습 판정 바꾸기는 카드와 연습 기록의 판정 목록을 한 트랜잭션으로 쓴다

## 이유
후보 2는 저장소가 응답마다만 바뀌어 목소리 띠와 끊김 표시가 늦고, 같은 상태를 화면과 서비스가 따로 읽어 엇갈릴 수 있다. 경계를 `RunningPractice` 가 바로 구현하면 화면 버튼도 알림 버튼과 같은 입구를 거쳐 끝내기 저장이 한 번만 일어난다. 테스트는 가짜 경계 하나로 화면 쪽 흐름을 본다.

연습 탭 화면 모듈이 말하기 연습 모듈의 ViewModel 을 들면 연습 탭 테스트마다 연습 기록 DB 를 띄워야 한다. 칸 하나로 두면 연습 탭은 그대로이고 카드는 말하기 연습 모듈에서 테스트한다.

화면에서만 숨겼다가 지우면 5초 안에 앱이 내려갈 때 사용자가 뺀 카드가 남는다. 바로 지우면 사용자가 본 대로 저장되고, 되돌리기는 들고 있던 카드를 다시 쓰면 복습 값까지 그대로 돌아온다.

판정 바꾸기는 판정 전 복습 값에서 다시 계산해 횟수를 빼고 더한다. 카드만 쓰이고 판정 목록이 옛 값으로 남으면 다음 바꾸기에서 다시 누른 횟수가 하나 어긋나서 한 트랜잭션으로 쓴다.

## 결과
- 되돌린 카드는 새로 만든 카드가 아니라 같은 카드라서 목록 순서도 그대로다. 5초가 지난 뒤에는 되돌릴 수 없다
- 닫은 시작 시트의 ViewModel 은 탭 화면이 백스택에서 빠질 때까지 남는다
- 연습 탭이 길어져 한 문항 연습의 Play 는 스크롤 아래로 내려간다
