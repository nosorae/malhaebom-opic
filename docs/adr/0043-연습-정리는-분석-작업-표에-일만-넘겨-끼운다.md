# 0043. 연습 정리는 분석 작업 표에 일만 넘겨 끼운다

- 상태: 채택
- 날짜: 2026-11-19

## 배경

연습이 끝나면 대화 전문으로 표현 카드를 만드는 정리 작업(F17.4)이 분석 작업 표(`analysis_job`, ADR 0032)에서 돌아야 한다. 작업 표와 비우기, 앱을 켤 때 되돌리기, 끝 알림은 모두 `engine/answer` 의 `AnalysisJobs` 에 있다. 그런데 카드 저장과 연습 기록은 `engine/speaking` 과 `engine/review` 에 있고, `engine/speaking` 이 `engine/answer` 를 의존하므로 `AnalysisJobs` 가 연습 정리를 직접 부를 수 없다. 정리는 다시 시도 간격(30초, 2분, 10분)도 답변 분석(30초부터 두 배)과 다르다.

## 후보

1. `engine/speaking` 에 정리 전용 작업 표와 비우기를 따로 둔다
2. `AnalysisJobs` 에 작업 종류 `Cards` 를 더하고, 보내기와 결과 쓰기만 `JobWork` 경계로 받는다. 작업 줄, 다시 시도, 되돌리기, 플랫폼 대기열은 지금 것을 쓴다

## 결정

2를 고른다.

- `JobWork` 는 다시 시도 간격, 대상 하나 처리, 실패로 끝남, 앱을 켤 때 다시 넣을 대상 넷이다. 구현은 `engine/speaking` 의 `CardJob` 하나다
- 연습 정리는 읽을 수 없는 응답(`Rejected`)도 다시 시도한다. 카드 만들기가 이미 한 번 다시 요청했고, 실패로 끝난 정리는 앱을 켤 때 다시 넣는다
- 연습 정리는 녹음 전송 동의(F1.3)를 보지 않는다. 보내는 것은 실시간 음성 전송 동의(F15.1)를 받고 한 연습의 대화 전문 글이다
- 카드 만들기 지시와 출력 스키마는 `engine/ai-gemini` 의 `GeminiCardWriter` 에 둔다. 종류와 틀린 유형 값은 엔진 enum 이름에서 만든다
- 모델이 카드가 없다고 답하면 다시 요청하지 않는다. 다시 요청은 응답을 읽을 수 없거나, 모델이 낸 카드가 검사(F17.2)를 하나도 통과하지 못했을 때만 한다
- 정리 끝 알림은 기존 분석 끝 알림 자리를 같이 쓰고, 정리 실패는 알리지 않는다. 연습 정리 화면이 생기기 전까지 알림은 연습 탭을 연다

## 이유

정리도 답변 분석처럼 Gemini 무료 키의 분당 한도를 같이 쓴다. 작업 표가 둘이면 두 비우기가 동시에 보내 한도에 걸리고, 앱을 켤 때 되돌리기와 끝 알림, Android 포그라운드 비우기, iOS 백그라운드 작업을 두 벌 만들어야 한다. 경계 하나를 두면 플랫폼 코드는 그대로이고 다시 시도 간격은 테스트 시계로 공통 코드에서 확인한다.

녹음 동의를 보면 녹음 동의 없이 말하기 연습만 쓰는 사용자의 정리가 늘 실패한다. 연습을 시작할 때 이미 실시간 음성 동의를 받았다.

모델이 카드 없음으로 답한 연습을 다시 물으면 고칠 것 없이 잘 말한 연습마다 요청을 한 번 더 쓴다. 다시 요청은 모델이 전문에 없는 문장을 지어냈을 때를 위한 것이다.

카드 지시를 시험 팩에 두면 시험 팩이 엔진의 카드 종류와 틀린 유형 이름을 따로 알아야 한다. 카드는 시험과 상관없는 말하기 연습의 산출물이라 어댑터에 둔다.

## 결과

- 진행 알림의 문구(답변을 분석하고 있어요)가 연습 정리 중에도 나온다. 정리 화면이 생길 때 문구를 작업 종류별로 나눈다
- 연습 기록에 끝낸 시각 열이 없어 다음 복습 시각은 시작 시각에 대화 시간을 더한 시각으로 센다. 일시정지한 동안 새벽 4시를 넘긴 연습은 하루 일찍 나온다
- 카드 지시 문장은 프롬프트 버전을 따로 남기지 않는다. 품질 확인 도구로 카드를 재기 시작하면 버전을 더한다
- 작업 종류가 더 생기면 같은 경계를 쓴다. 다른 엔진 작업이 둘을 넘으면 `JobWork` 를 종류별 지도로 바꾼다
