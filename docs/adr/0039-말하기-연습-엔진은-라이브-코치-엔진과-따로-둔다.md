# 0039. 말하기 연습 엔진은 라이브 코치 엔진과 따로 둔다

- 상태: 채택
- 날짜: 2026-11-19

## 배경

말하기 연습(F16)과 라이브 코치(F11)는 둘 다 Gemini Live 로 코치와 음성 대화를 한다. 연결, 이어 붙이기 핸들, 마이크와 재생, 사용량 계산처럼 겉으로 같은 부분이 많아서 `engine/coach` 에 연습 모드를 더하는 것이 먼저 떠오른다.

그러나 세션의 모양이 다르다. 코치는 질문 하나를 두고 경험 끌어내기, 표현 코칭, 리허설, 피드백 네 단계를 지나 스크립트를 만들고, 단계마다 연결을 새로 연다(ADR 0036). 리허설 단계는 연결을 닫고 녹음기로 녹음한다. 말하기 연습은 주제 하나를 두고 말로 복습, 대화, 마무리 세 단계를 연결 하나로 잇고, 대답 없음, 이어폰 버튼, 오디오 끼어듦으로 일시정지하며, 일시정지 10분과 남은 5분, 1분 같은 시간 규칙이 있다. 결과물도 스크립트가 아니라 표현 카드다.

## 후보

1. `engine/coach` 의 `CoachPhase` 와 상태 계산에 연습 단계와 규칙을 더하고 모드 값으로 가른다
2. 새 모듈 `engine/speaking` 을 만들고, 둘이 같이 쓰는 것은 아래 라이브러리(`libs/live-gemini`, `libs/duplex-audio`)에만 둔다

## 결정

2를 고른다.

- `engine/speaking` 은 `engine/coach` 를 의존하지 않는다. 단계, 상태, 일어난 일, `reduce` 를 따로 정의한다
- Live 연결 설정(말 끝 판정, 끼어들기)은 `libs/live-gemini` 의 `LiveConfig` 에 선택 값으로 더해, 값을 주지 않으면 코치가 지금과 같은 setup 을 보내게 한다
- 두 엔진에 같은 코드가 생기면 엔진에 공용 모듈을 만들지 않고, 라이브러리로 내릴 수 있는 것만 내린다

## 이유

후보 1은 코치의 상태 계산 함수에 모드 분기가 들어가서, 연습 규칙을 고칠 때마다 코치의 단계 전환 테스트를 다시 봐야 한다. 코치는 이미 실기기에서 맞춘 단계 전환과 연결 교체(F11.5~F11.8)가 있고, 연습의 일시정지 규칙이나 시간 규칙이 그쪽으로 새면 코치가 백그라운드에서 멈추지 않거나 리허설 중에 연결을 여는 회귀가 생긴다. 단계 수, 연결 수명, 일시정지 원인, 결과물이 모두 달라서 모드 값 하나로 가르면 거의 모든 분기에 모드 검사가 붙는다.

따로 두면 각 엔진의 `reduce` 를 자기 규칙만으로 테스트한다. 같이 쓰는 연결과 오디오는 이미 라이브러리에 들어 있으니 따로 두어도 다시 짜는 코드는 상태 계산과 실행 쪽 정도다.

## 결과

연결 열기, 사용량 더하기, 받아쓰기 쌓기 같은 실행 쪽 코드가 두 엔진에 비슷하게 생긴다. 셋째 음성 기능이 생기거나 같은 버그를 두 곳에서 고치는 일이 반복되면, 그 부분만 라이브러리나 작은 공용 모듈로 내린다.

`LiveConfig` 에 더하는 값은 코치 테스트가 그대로 통과하는지로 확인한다(노드 `live-config`).
