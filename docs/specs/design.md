# 설계

모의고사와 한 문항 연습, 두 사이클로 만든다. 둘 다 사용자가 앱에서 직접 시작한다. 두 사이클 모두 "답변 하나"를 남기고, 리포트와 다음 출제는 쌓인 답변 전체를 본다. 요구사항 번호는 `product.md` 를 가리킨다.

## 1. 범위

첫 버전에 넣는 것은 다섯이다.

1. 모의고사: 실제 시험 순서 그대로, 15문항, 이어 보기
2. 한 문항 연습: 앱에서 언제든 질문 하나를 푼다
3. 리포트: 답변별 피드백이 쌓이고, 모의고사는 회차 등급이 붙는다
4. 기록: 회차별 예상 등급 변화
5. 약점 출제: 점수가 낮은 문항 유형을 다음 모의고사와 한 문항 연습에 더 낸다

넣지 않는 것은 서버, 계정, 3문항짜리 짧은 회차다.

## 2. 처음 설정

1. AI 제공사를 고르고 API 키를 넣는다. 첫 버전은 Gemini 하나만 보인다. 서버 없이 사용자가 자기 키를 쓴다. 키는 제공사 이름으로 구분해 Android Keystore, iOS Keychain 으로 보호한다(F1.1, F1.2). 화면 위쪽 안내 카드가 서버 없이 내 키로 보내는 이유와 요금이 잡히는 곳을 알리고, 키 받는 순서 세 단계와 시스템 브라우저로 키 발급 페이지를 여는 "키 받기" 버튼을 둔다. 발급 주소는 제공사 정보(`KeyProvider.keyPageUrl`)에 있어 제공사를 더하면 주소도 함께 더한다. 입력란은 키를 가리지 않는다. 40자 넘는 키를 붙여 넣은 뒤 다 들어갔는지 눈으로 확인하게 하려는 것이다. 붙여 넣으며 딸려 온 공백, 역슬래시, 눈에 안 보이는 문자는 저장 전에 뺀다
2. 녹음한 음성이 Google Gemini 로 간다는 안내에 동의한다. 무료 키로 보낸 음성은 Google 이 제품 개선에 쓰고 사람이 들을 수 있다. 두 플랫폼 모두 마이크 권한 요청보다 먼저 묻는다(F1.3)

앱을 켜면 시스템 스플래시를 잡아 둔 채 저장된 키와 동의 상태만 읽어 갈 곳을 정한다(F1.0). 서베이는 모의고사마다 하고, 설정에서도 같은 흐름으로 저장한 답을 보고 바꾼다. 저장한 답은 다음 모의고사 서베이를 채우고 한 문항 연습 주제에 쓴다.

## 3. 모의고사

서베이 구성은 실제 시험 구성을 참고했다(https://www.opic.or.kr 영어 튜토리얼). 실제 시험 화면의 선택지 이름과 같은지는 확인하지 못했다.

| 순서 | 화면 | 실제 시험과 같은 점 | 앱에서 다르게 둔 점 |
|---|---|---|---|
| 1 | 서베이 | 매번 한다. Part 1~2 는 고른 답에 따라 하위 질문이 이어지고 Part 3 은 거주, Part 4 는 네 묶음(여가 2개 이상, 취미 1개 이상, 운동 1개 이상, 휴가나 출장 1개 이상, 모두 46개)에서 합쳐서 12개 이상 고른다 | 지난 선택을 미리 채운다. 매번 12개를 새로 고르는 건 연습에 도움이 안 된다. 한 화면에 질문 하나, 묶음 하나다. 질문 문장은 이 앱의 말로 썼다 |
| 2 | 수준 선택 | 1~6단계, Next 뒤 되돌릴 수 없다 | 단계별 샘플 음성은 없다 |
| 3 | 점검과 연습 | 마이크 확인, 채점 안 하는 연습 문항 1개 | |
| 4 | 1~7번 | 아래 문항 규칙 | 40분 타이머가 여기서 시작한다 |
| 5 | 난이도 재조정 | "쉬운/비슷한/어려운 질문" 셋 중 하나 | |
| 6 | 8~15번 | 아래 문항 규칙 | |
| 7 | 끝 | | 리포트가 바로 나온다 |

문항 규칙은 실제 시험과 같다. 질문 글자는 화면에 없다. Play 를 누르면 질문이 나오고 끝나면 녹음이 저절로 시작된다. 녹음 시작 5초 안에 다시 듣기를 한 번 할 수 있다. Next 는 녹음 시작 10초 뒤에 켜진다. 지나간 문항으로 돌아갈 수 없다.

실제 동작을 확인하지 못한 세 곳은 이렇게 정했다.

- 문항별 답변 타이머: 기본은 끄고 설정에서 켠다
- 40분이 지나면: 그때까지 답한 문항만 채점하고 남은 문항은 리포트에 "시간 부족"으로 표시한다
- 앱이 꺼져 있는 동안: 40분 타이머가 멈춘다

## 4. 이어 보기

모의고사 진행은 공통 코드의 함수 하나가 계산한다. 지금 상태와 일어난 일(Play, Next, 다시 듣기, 재조정 선택, 앱 꺼짐, 시간 끝)을 받아 다음 상태를 돌려주고, 저장이나 화면 같은 다른 일은 하지 않는다. 상태가 바뀔 때마다 통째로 Room 에 저장하고, 앱을 켜면 저장된 상태에서 다시 시작한다. Room 에 저장된 상태가 진실 공급원이다.

이렇게 하면 "7번에서 껐다 켜면 재조정 화면부터" 같은 경우를 기기 없이 단위 테스트로 전부 확인할 수 있다. 일어난 일을 모두 기록하고 켤 때 다시 계산하는 방식은 시험 한 회짜리 앱에 비해 크다. 화면이 상태를 들고 있다가 저장하는 방식은 앱이 갑자기 죽으면 저장 시점을 놓친다.

녹음은 몇 초 단위 조각 파일로 바로바로 쓴다. 답하는 도중 앱이 꺼지면 쓰던 조각 하나만 잃는다. 조각을 나눌 때 녹음기를 멈췄다 다시 열지 않는다. 그 사이마다 약 0.07초가 빠져 말 한가운데 음절이 잘린다(11절). 녹음기는 답변 하나 동안 그대로 두고 받은 소리를 쓰는 파일만 바꾼다. 분석 요청에는 조각을 기기에서 한 파일로 이어 붙여 보낸다. 다시 켜면 같은 문항에서 이어 녹음하고, 그 문항에서 다시 듣기를 안 썼으면 질문을 한 번 다시 들을 수 있다. 끊긴 지점은 분석 요청에 표시해서 그 구간을 말 멈춤으로 세지 않게 한다.

## 5. 한 문항 연습

1. 연습 탭에서 언제든 Play 를 누른다
2. 질문 하나가 나오고 모의고사와 같은 규칙으로 답한다
3. 끝나면 그 답변의 피드백을 바로 보여 준다

## 6. 데이터

기본 단위는 답변 하나다.

- **답변**: 질문, 문항 유형, 주제, 어느 사이클에서 나왔는지, 녹음 조각 목록, 전문, 피드백, 유형별 점수, 분석한 제공사와 모델 id 와 promptVersion
- **모의고사 회차**: 서베이 선택, 수준 선택, 재조정 선택, 답변 순서, 남은 시간, 진행 상태, 회차 등급

녹음 파일은 기기에만 둔다.

## 7. AI 분석

피드백은 답변마다, 등급은 모의고사 전체로 나눠 받는다. 실제 오픽은 문항별 점수 없이 시험 전체를 듣고 등급 하나를 준다. AL 은 모든 문항에서 무너지지 않아야 받는 등급이라 답변 점수 평균으로는 못 잡는다.

- **답변 분석**: Next 를 누르면 뒤에서 바로 보낸다. 한 문항 연습 답변도 같은 경로다. 결과는 전문, 문법 교정, 한 등급 위 표현, 시제 유지, 문단 길이, 말 속도, 멈춘 시간, 롤플레이에서 한 질문 수
- **회차 등급**: 15번이 끝나면 답변 피드백과 녹음을 묶어 한 번 보낸다. 결과는 NL 에서 AL 까지의 예상 등급 범위와, 어느 문항에서 무너졌는지
- **출력 검사**: 교정의 원문 구절이 전문에 있는지, 값 범위와 문항 수가 맞는지 앱 코드가 확인한다(F5.4)
- **실패 처리**: 분석이 실패하면 그 답변만 다시 보낸다. 오프라인이면 녹음은 그대로 하고 분석은 대기열에 넣었다가 연결되면 보낸다. 키가 없거나 틀리면 설정 화면으로 보낸다

### 7.1 두 단계로 나눈 분석 구조

첫 버전 제공사는 Gemini 하나다. 다른 제공사(Claude, OpenAI)를 나중에 붙일 수 있게 분석을 두 단계로 나눈 포트를 `engine/answer` 에 둔다(ADR 0019).

| 단계 | 하는 일 | 결과 |
|---|---|---|
| 받아쓰기 | 녹음에서 전문과 단어마다 시작, 끝 시각을 뽑는다 | 전문, 단어 시각 |
| 글 분석 | 전문(필요하면 단어 시각을 글로)을 받아 교정, 한 등급 위 표현, 체크리스트, 등급을 낸다 | 피드백, 체크 결과 |

경로는 둘이다.

- **한 번 호출 경로**: 음성을 직접 듣는 모델(Gemini 일반 모델)이 녹음을 받아 두 단계를 한 요청에서 끝낸다. 발음까지 본다. 첫 버전은 이 경로만 실제로 쓴다
- **두 단계 경로**: 음성을 못 듣는 제공사를 쓸 때다. 기기 음성 인식이나 받아쓰기 전용 모델로 받아쓴 뒤 글만 보낸다. 발음 항목은 "평가 안 함"으로 표시한다

멈춘 시간과 말 속도는 단어 시각만 있으면 앱이 직접 계산할 수 있다. 두 단계 경로에서는 이 계산을 앱이 맡는다. 한 번 호출 경로의 멈춤, 속도는 모델 답에 맡긴다. 미리 확인 노드 `s1` 에서 모델이 직접 답한 멈춤 위치가 실제와 0.4초 안이었고, 단어 시각까지 받으면 출력 토큰이 분석 한 번보다 많아졌다(11절).

첫 버전에서 두 단계 경로가 실제로 맞물리는지는 테스트 안의 "음성을 못 듣는 가짜 제공사"로 받아쓰기부터 결과 저장까지 끝까지 돌려 확인한다. Claude, OpenAI 실제 구현은 하지 않는다.

### 7.2 모델 고르기와 기록

설정에서 분석 모델을 고른다. 목록은 앱이 들고 있는 검증된 목록이다. 항목마다 제공사(`gemini`), 모델 id, 표시 이름, 음성 직접 분석 여부, 안정 또는 미리보기를 둔다.

목록 API 를 그대로 쓰지 않는 이유는 둘이다. 제공사의 모델 목록 응답에는 오디오 입력을 받는지 알려 주는 값이 없다. 그리고 출력 검사(교정 구절이 전문에 있는지, 값 범위)가 통과하는지는 모델마다 품질 확인 도구(`tools/eval`)로 돌려 봐야 안다. 목록 API 는 고른 모델이 아직 있는지 확인하는 데만 쓴다.

기본값은 안정 모델이다. 미리보기 모델은 2주 공지로 내려갈 수 있어서 고를 때 안내한다. 고른 모델이 내려가 요청이 실패하면 기본 모델로 돌리고 알린다.

답변 결과마다 제공사, 모델 id, promptVersion 을 저장한다. 리포트와 기록 화면에 어느 모델이 분석했는지 보이고, 한 회차 안에서 답변 분석 모델이 섞였으면 회차 등급 옆에 표시한다. 모델마다 채점 경향이 달라서 기록 화면의 등급 변화가 모델 교체 때문인지 실력 때문인지 가려 볼 수 있어야 한다.

무료 키로 보낸 음성이 제품 개선에 쓰일 수 있다는 안내는 음성 전송 동의 화면에 두고 키 입력, 모델 선택 화면에서는 그리로 연결한다.

## 8. 출제

질문은 AI 가 기출 유형대로 만든다. 서베이 주제, 수준, 재조정 선택, 약점 점수를 넣고 문항 유형 순서(자기소개, 3문항 세트 셋, 롤플레이 셋, 비교와 사회 이슈 둘)를 맞춰 받는다.

회차 질문은 세 몫으로 나눠 앞질러 받는다. 점검과 1번은 내장 문항, 2~7번은 1번 Play 때, 8~15번은 6번 Play 때 재조정 선택지마다 요청해 둔다(ADR 0030).

기출 원문은 앱에 넣지 않는다. 공개된 교재와 기출 모음은 무단 전재 금지이거나 라이선스가 없다. 대신 사용자가 자기 문항 파일을 불러올 수 있게 한다.

질문 음성은 미리 만든 Gemini 음성으로 읽는다. 내장 문항은 앱에 넣고, 모델이 낸 문항은 출제를 받을 때 미리 받는다. 받지 못하면 기기 음성으로 읽어서 오프라인에서도 시험이 멈추지 않는다([ADR 0031](../adr/0031-질문은-미리-만든-Gemini-음성으로-읽고-못-받으면-기기-음성.md)).

### 9.2 디자인 시스템

Montage(MIT, v4.0.0 태그 고정)의 토큰과 컴포넌트를 Compose 공통 코드로 옮겨 `ui/design` 에 둔다(ADR 0018).

- 옮기는 것: 색 238개와 다크 색 148개(XML 값을 Kotlin 상수로), Pretendard 글꼴 4종, 아이콘 vector, 컴포넌트
- 안 옮기는 것: 원티드 로고, 워드마크, 로딩 애니메이션
- 고지: MIT 전문과 "Copyright (c) Wanted Lab, Inc.", Pretendard SIL OFL 1.1 을 `THIRD_PARTY_LICENSES.md` 에, "디자인 시스템: Montage by Wantedlab (MIT)" 를 앱 정보 화면과 README 에
- 강조색: 시맨틱 색 가운데 brand 계열만 우리 주홍으로 바꾼다. 라이트 `#C83F1A`(버튼, 글자), 장식 `#E9572B`(그래프, 진행 막대. 글자 배경에는 쓰지 않는다), 다크 `#FF8A62`(위 글자는 검정 계열). 값과 대비는 `product.md` 의 「디자인 시스템」 절에 있다

네이티브로 그리는 곳은 하단 탭(Android Material 3 Expressive NavigationBar 계열, iOS SwiftUI TabView 와 Liquid Glass)과 뒤로가기(Android 예측 뒤로가기, iOS 뒤로 버튼과 가장자리 스와이프)다. 이 두 곳은 사용자가 OS 마다 손에 익은 동작이라 플랫폼 것을 쓴다. 하위 화면의 탭 표시도 플랫폼을 따른다. Android 는 최상위 탭 화면(모의고사, 연습, 표현, 기록, 설정)에서만 탭을 보이고 하위 화면에서 숨기고, iOS 는 리포트 상세 같은 하위 화면에도 탭을 남긴다. 시험 진행과 녹음 화면은 두 플랫폼 모두 탭 없는 전체 화면이다. 이 차이는 앱 틀의 화면 경로 표 하나에 두고 화면 모듈은 모른다. 나머지 화면 안 요소는 모두 Montage 로 그린다. 공유 시트와 파일 고르기는 네이티브 후보로만 둔다.

네이티브 부분이 관리하기 어려우면 Montage 로 완전히 통일한다. 미리 확인 노드 `s4` 에서 Montage 화면 위에 네이티브 탭과 뒤로가기를 얹어 보고, `product.md` 「디자인 시스템」 절의 기준 넷 가운데 하나라도 걸리면 통일로 바꾸고 이 절에 적는다.

확인 결과 네이티브를 유지한다. `s4` 에서 기준 넷 모두 해당하지 않았다(`spikes/native-chrome/result.json`). iOS 시험 화면의 탭 숨기기는 보일 때 `.automatic`, 숨길 때 `.hidden` 으로 쓴다.

화면 모드는 설정에서 시스템 따라가기, 라이트, 다크 중에 고르고 기본값은 시스템 따라가기다(F9.1). Montage 의 라이트, 다크 토큰을 이 값으로 고른다.

모든 화면에서 edge-to-edge 를 켠다. 배경과 스크롤 콘텐츠는 시스템 바 아래까지 그리고, 버튼과 글은 시스템 바, 컷아웃, 키보드 인셋 안쪽에 둔다. iOS Compose 화면도 배경은 안전 영역 밖까지, 콘텐츠는 안전 영역 안에 둔다.

### 12.1 연습 세션 단계와 상태

연습 한 번은 주제 하나다. 진행은 공통 코드의 순수 함수 `reduce(지금 상태, 일어난 일)` 하나가 계산한다. 모의고사 진행(4절)과 같은 방식이라 단계 전환, 명령, 시간 처리를 기기 없이 단위 테스트로 본다. 연결을 열고 닫고 저장하는 일은 이 함수 밖의 실행 쪽이 한다.

| 단계 | 들어가는 때 | 하는 일 | 나가는 때 |
|---|---|---|---|
| 말로 복습 | 시작 때 말로 복습이 켜져 있고 오늘 복습할 카드 가운데 처음 봄이 아니오인 카드가 있을 때 | 그런 카드 앞 3장마다 한국어 상황을 영어로 말하게 하고, 판정하고, 정답을 한 번 들려주고 따라 말하게 한다. 판정으로 FSRS 를 고치고 판정 전 복습 값을 말로 복습 결과에 남긴다(F16.8) | 고른 카드를 다 풀었을 때 |
| 대화 | 말로 복습이 끝났거나 건너뛸 때 | 7~14일 지난 주제를 먼저, 없으면 가장 적게 연습한 주제를 골라 여섯 유형 가운데 정한 시간에 맞는 수만큼 묻고 꼬리 질문을 잇는다(F16.5, F16.6) | 남은 시간이 5분일 때 |
| 마무리 | 남은 시간 5분 | 첫 질문을 다시 묻는다(2회째). 2회째가 끝나고 2분 넘게 남았고 정한 시간이 10분이 아니면 한 번 더 묻는다(3회째, F16.20). 1분이 남으면 마무리 문장 하나 | 남은 시간 0, 끝내기 |

| 상태 | 뜻 | 바뀌는 때 |
|---|---|---|
| 듣는 중 | 마이크 소리를 보내고 사용자 말을 기다린다 | 시작, 다시 시작, 코치 말이 끝남 |
| 코치가 말하는 중 | 코치 음성을 재생한다 | 코치 음성이 오기 시작함 |
| 일시정지 | 말소리는 보내 코치가 다시 시작과 그만할래만 듣게 하고, 대화 시간, 대답 없음, 내가 말한 시간은 멈춘다. 끊김으로 멈췄으면 보내지 않는다 | 잠깐, 이어폰 한 번 누르기, 알림 버튼, 대답 없음 두 번, 오디오 끼어듦, 다시 연결 3번 실패 |

일어난 일은 시작, 시간 흐름(단조 시계), 사용자 말 시작과 끝, 코치 말 시작과 끝(재생한 길이), 대답 없음, 확인 질문, 질문함(문장과 유형), 명령 일곱(F16.9), 말로 복습 판정, 표현 저장, 오디오 끼어듦과 끝남, 연결 끊김, 다시 연결 성공, 끝내기다. 계산 규칙은 이렇다.

- 대답 없음 횟수가 2가 되면 일시정지로 간다. 사용자가 말하면 0으로 돌린다. 확인 질문 뒤에는 올리지 않는다(F16.12, F16.21)
- 사용자 말이 끝나면 그 길이를 내가 말한 시간에, 코치 말이 끝나면 실제로 재생한 길이를 코치가 말한 시간에 더한다(F16.24)
- 같은 질문을 말한 횟수는 3을 넘지 않는다. 정한 시간이 10분이면 2를 넘지 않는다(F16.20)
- 일시정지한 시각에서 10분이 지나면 끝낸다
- 남은 시간 = 정한 시간 - 대화 시간. 대화 시간은 일시정지 동안 늘지 않는다(F16.13)
- 연결이 끊기면 다시 연결 횟수를 하나 올린다. 3번을 넘으면 일시정지하고 "끊김" 표시를 남겨 알림이 다시 연결 버튼을 보이게 한다(F16.15)
- 끝내기는 어디서 오든 하나다. 진행 중인 연습을 연습 기록으로 옮기고 연습 정리 작업을 넣는다(F16.11)

연결은 연습 하나에 Live 연결 하나를 이어 쓴다. 단계가 바뀌면 지시를 다시 열지 않고 코치에게 도구 응답으로 다음 단계를 알린다. 연결이 바뀌거나 끊겨도 이어 붙이기 핸들로 잇고, 길어진 대화는 연결의 맥락 압축이 덜어 낸다. 처음 지시에는 서베이 주제와 업무 주제, 주제별 마지막 연습 시각과 지난번 첫 질문, 단계 지시, 처음 봄이 아니오인 오늘 복습할 카드 앞 3장, 자주 틀리는 유형 상위 셋, 문단이 끊기거나 시제가 무너진 일이 많은 유형, 연습 중 문법 짚기 값(F16.22)을 넣는다. 주제별 마지막 연습 시각은 `speaking_session` 에서 주제별로 가장 늦은 `startedAt` 을 묻는 쿼리 하나로 얻고 따로 표를 두지 않는다. 코치 프로필과 지시 문장은 시험 팩(`packs/opic-en`)에 둔다.

음성 명령과 표현 저장은 코치의 도구 호출로 받는다. 코치가 고칠 표현 후보를 적는 것도 도구 호출이라 연습 중 사용자에게 들리지 않는다(F16.7).

### 12.2 서비스가 세션을 소유하는 구조

연습 세션은 화면 ViewModel 이 아니라 앱 범위 객체 하나와 플랫폼 서비스가 들고 있다([ADR 0038](../adr/0038-연습-세션은-화면이-아니라-서비스가-소유한다.md)). 화면은 세션 상태를 지켜보고 버튼을 명령으로 넘기기만 한다.

| 층 | 모듈 | 하는 일 |
|---|---|---|
| 엔진 | `engine/speaking` | `reduce` 와 실행 쪽 `SpeakingSession`. Live 연결, 오디오, 저장소, 시계를 받아 돌린다. 플랫폼을 모른다 |
| 앱 공통 | `apps/opic/shared` | 앱 범위 `RunningPractice` 하나가 지금 도는 세션을 들고 `StateFlow` 로 낸다. 시작, 일시정지, 다시 시작, 끝내기, 다시 연결을 받는다 |
| Android | `apps/opic/androidApp` | 마이크 포그라운드 서비스가 `RunningPractice` 를 붙잡고 진행 알림(일시정지, 끝내기, 다시 연결)을 띄운다. MediaSession 으로 이어폰 한 번 누르기를 받고, 오디오 포커스를 잃거나 전화가 오면 일시정지를 넣는다 |
| iOS | `apps/opic/iosApp` | 백그라운드 오디오로 세션을 잇는다. 오디오 세션 끼어듦과 이어폰 연결 바뀜을 일시정지로 넣고, `MPRemoteCommandCenter` 로 이어폰 버튼을 받는다. 진행 표시는 잠금 화면 Live Activity 이고 위젯 확장(F19.6)에 같이 둔다 |
| 화면 | `ui/feature-speaking` | 시작 시트, 연습 중 화면, 연습 정리 화면. 세션을 만들지 않고 `RunningPractice` 를 지켜본다 |

흐름은 이렇다.

1. 시작 시트에서 시작을 누르면 화면이 보이는 동안 `RunningPractice.start` 를 부르고, Android 는 여기서 포그라운드 서비스를 띄운다. 화면이 보이지 않을 때는 시작하지 않는다(F16.4)
2. 서비스가 떠 있는 동안 세션은 화면과 상관없이 돈다. 연습 중 화면을 떠나도, 화면을 꺼도 세션은 그대로다
3. 끝내기가 오면 세션이 연습 기록과 정리 작업을 저장하고 `RunningPractice` 가 비고, 서비스가 내려간다
4. 앱 프로세스가 죽으면 세션도 사라진다. 다음에 앱을 켜면 `speaking_active` 줄을 보고 연습 중 화면으로 데려가고, 화면이 보이는 상태에서 서비스를 다시 띄워 같은 줄과 핸들로 이어 간다(F16.16)

효과음 다섯(F16.19)은 플랫폼 쪽 짧은 소리 파일이고 세션 상태가 바뀔 때 앱 공통이 고른다.

### 12.3 표현 카드와 FSRS

카드와 복습 계산은 `engine/review` 에 순수 코드로 둔다. Live 연결도 화면도 모른다.

| 값 | 뜻 |
|---|---|
| 종류 | 고칠 표현, 몰랐던 표현, 정형 표현, 더 자연스럽게 |
| 내가 한 말, 더 나은 표현, 한국어 뜻, 상황 | 카드 내용. 내가 한 말은 대화 전문에 그대로 있는 문장이다(F17.2) |
| 틀린 유형 | 시제, 관사, 낱말 선택, 연결어, 문장 구조. 고칠 표현에만 둔다. 한국어로 말한 것은 몰랐던 표현 카드가 된다(F16.23) |
| 처음 봄 | 만들 때 예. 처음 복습의 다음 버튼, 표현 상세 열기, 이미 알아요에서 아니오로 바뀐다. 예인 카드는 말로 복습에 나오지 않는다 |
| 복습 값 | 난이도, 안정도, 다음 복습 시각, 마지막 복습 시각 |
| 복습 횟수, 다시 누른 횟수, 보관 여부 | 상세 화면과 오늘 복습 고르기에 쓴다 |

간격은 FSRS 로 계산한다. 평가 넷(다시, 어려움, 알았음, 쉬움)이 Again, Hard, Good, Easy 다. 표현 상세의 이미 알아요는 쉬움 평가 하나다. 처음 봄 카드의 다음 버튼은 FSRS 를 부르지 않고 다음 복습 시각만 다음 날 새벽 4시로 옮긴다. 말로 복습 판정을 바꾸면(F17.10) 남겨 둔 판정 전 복습 값에서 바뀐 평가로 다시 계산한다. 목표 기억률은 복습 양 설정으로 고른다(적게 0.85, 보통 0.90, 많이 0.95). 가중치는 FSRS 기본값을 쓰고 사용자 기록으로 다시 맞추지 않는다. 카드가 적은 동안은 맞춘 값이 기본값보다 나아지지 않는다. KMP 에서 쓸 수 있는 FSRS 라이브러리가 있으면 쓰고, 없으면 수식을 옮기고 알려진 입력과 결과 쌍으로 확인한다.

오늘 복습할 카드는 보관하지 않은 카드 가운데 다음 복습 시각이 지난 것을, 지금 기억할 확률(FSRS retrievability)이 낮은 순으로 세운다. 처음 봄이 예인 카드는 오늘 새로 보여 준 수와 합쳐 10장까지만 넣되, 다음 복습 시각에서 하루가 넘게 지난 것은 상한 없이 맨 앞에 둔다. 그날 복습한 수를 빼 하루 30장까지 자른다. 한 묶음은 앞 6장이다(F18.2, F18.4). 말로 복습(F16.8)은 같은 계산에서 처음 봄이 아니오인 앞 3장을 쓰고, 코치 판정은 맞으면 알았음, 틀리면 다시로 넘긴다.

하루는 기기 시간대의 새벽 4시에 바뀐다(F18.11). 날짜 번호는 시각에서 4시간을 뺀 뒤 로컬 날짜로 센다([ADR 0040](../adr/0040-로컬-날짜는-kotlinx-datetime-으로-센다.md)의 날짜 번호를 그대로 쓴다). `localDay` 한 곳에서 처리하고, 오늘, 다음 날, 복습한 날, 이번 주 계산은 모두 이 함수를 거친다.

카드 만들기(F17)는 연습이 끝난 뒤 분석 작업 표(`analysis_job`, ADR 0032)에 연습 정리 작업으로 들어간다. 다시 시도 간격은 30초, 2분, 10분이다. 요청과 출력 스키마는 `engine/ai-gemini` 에 두고, 내가 한 말이 전문에 있는지와 같은 카드가 있는지는 엔진이 검사한다. 고칠 표현 8장, 더 자연스럽게 2장 상한도 엔진이 자른다. 모델은 카드마다 같은 유형이 몇 번 나왔는지와 뜻 전달을 막았는지를 함께 내고, 엔진은 그 순서로 고른 뒤 남은 고칠 표현 수를 이번에 넘긴 오류 수로 적는다(F17.3). 모델이 상한을 지킨다고 믿지 않는다. 표현을 쓴 횟수(F17.9)는 모델에 맡기지 않고 엔진이 대화 전문에서 센다. 이 상한과 규칙들의 이유는 [ADR 0041](../adr/0041-말하기-연습-설계를-제2언어-습득-연구-결과에-맞춘다.md)에 있다.

### 12.4 저장: Room version 5

Room 을 version 4 에서 5로 올리고 표 4개를 더한다. 아직 출시 전이라 F16~F18 을 고치며 늘어난 열은 version 6 을 따로 두지 않고 version 5 의 표 정의와 4에서 5로 옮기는 SQL 에 바로 넣는다([ADR 0042](../adr/0042-출시-전이라-Room-version-5-를-고쳐-쓴다.md)). 옛 표는 고치지 않으므로 이전 SQL 은 `CREATE TABLE` 넷뿐이다. 표는 `OpicDatabase` 에 더하고, 카드와 복습한 날의 저장소는 `engine/review` 에, 연습 표의 저장소는 `engine/speaking` 에 둔다. 코치 표(`engine/coach` 의 `CoachStore`)와 같은 모양이다. 모두 기기에만 두고 다른 기기와 맞추지 않는다(F17.8).

| 표 | 한 줄 | 열 |
|---|---|---|
| `expression_card` | 표현 카드 하나 | `id`, `kind`(고칠 표현, 몰랐던 표현, 정형 표현, 더 자연스럽게), `said`, `better`, `meaning`, `errorType`, `context`, `practiceId`, `createdAt`, `firstSeen`(처음 봄), `archived`, `difficulty`, `stability`, `dueAt`, `lastReviewedAt`, `reviewCount`, `againCount` |
| `speaking_session` | 끝난 연습 하나(연습 기록) | `id`, `startedAt`, `talkTimeMs`, `userTalkMs`(내가 말한 시간), `coachTalkMs`(코치가 말한 시간), `topic`, `topicSwitches`(주제 바꾼 횟수), `questions`(JSON. 질문마다 문장, 유형, 같은 질문을 말한 횟수, 문단이 끊기거나 시제가 무너졌는지), `transcript`(JSON), `oralReviews`(JSON. 카드마다 카드 id, 더 나은 표현, 판정, 판정한 시각, 판정 전 복습 값), `expressionUses`(표현을 쓴 횟수), `cardCount`, `skippedErrors`(이번에 넘긴 오류 수), `reportCount`(틀린 지적 신고 수), `cardStatus`(정리 전, 정리 중, 정리 끝, 정리 실패), `usage`(JSON), `costUsd` |
| `speaking_active` | 진행 중인 연습. 많아야 한 줄 | `id`, `startedAt`, `plannedMinutes`, `audioRoute`(이어폰, 스피커), `phase`, `status`, `pausedAt`, `talkTimeMs`, `userTalkMs`, `coachTalkMs`, `silenceCount`, `reconnects`, `topic`, `topicSwitches`, `questions`(JSON, 질문마다 말한 횟수 포함), `currentQuestion`(마지막으로 물은 질문의 위치), `transcript`(JSON), `savedCount`, `resumeHandle`, `handleAt`, `usage`(JSON), `reviewCardIds`(JSON), `oralReviews`(JSON) |
| `review_day` | 복습을 한 장 이상 끝낸 날 하나 | `day`(1970-01-01 을 0 으로 센 로컬 날짜 번호, 기본 키, [ADR 0040](../adr/0040-로컬-날짜는-kotlinx-datetime-으로-센다.md)). 8주보다 오래된 줄은 쓸 때 지운다 |

시각은 epoch 밀리초다. 내 말 비율은 `userTalkMs` 와 `coachTalkMs` 로 계산하고 열을 두지 않는다. 주제별 마지막 연습 시각도 `speaking_session` 의 `topic`, `startedAt` 으로 묻고 표를 두지 않는다. 진행 중인 연습은 응답마다 통째로 덮어써서 프로세스가 죽으면 마지막 응답까지 남는다. 끝내기는 `speaking_active` 줄을 지우고 `speaking_session` 줄과 정리 작업을 넣는 일을 한 트랜잭션으로 한다. 4에서 5로 옮기는 테스트는 Android 와 iOS 에서 같이 돈다.

복습 화면의 이번 묶음(카드 id 6개)과 지금 순번은 설정 저장소에 둔다. 두 플랫폼 모두 프로세스가 끝나도 남고, 표를 하나 더 만들 만큼 크지 않다. 평가는 누를 때마다 카드 줄에 바로 쓴다(F18.8). 설정 값(기본 연습 시간, 말 끝 기다림, 말로 끊기, 연습 중 문법 짚기, 시작 때 말로 복습, 복습 양, 알림 받기와 시각, 소리 없이)은 기존 설정 저장소에 둔다.

### 12.5 Live 연결 설정과 스피커 모드

말 끝 판정은 연결 setup 의 `realtimeInputConfig.automaticActivityDetection` 으로 넘긴다. 침묵 판정 시간은 말 끝 기다림(0.7, 1, 1.5초), 말 시작과 말 끝 감도는 이어폰이면 기본값, 스피커면 낮음이다. 말로 끊기가 꺼져 있으면 `activityHandling` 을 끼어들지 않음으로 둔다. 값을 주지 않으면 지금 라이브 코치와 같은 setup 이 나간다(F16.17, F20.5).

스피커 모드(F20)는 `libs/duplex-audio` 에서 처리한다. 기기 에코 제거와 소음 억제를 켜고, 기기 안 말소리 감지로 말소리가 아닌 조각은 보내지 않는다. 코치가 말하는 중의 끊기는 서버 판정에 맡기지 않고 기기가 정한다. 내 말소리가 0.6초 넘게 이어질 때만 재생을 멈추고 연결에 알린다. 0.6초는 실기기에서 다시 잰다.
